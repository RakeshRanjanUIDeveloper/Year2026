React + Redux + Saga — generic flow

A reliable reference for building any React + Redux + Saga application

1
Component UI layer
FeatureComponent.jsx
  • User interacts — click, submit, change
  • useDispatch() → calls action creator first, then dispatch(featureRequest(payload)) sends action to Store
  • useSelector(state => state.feature.loading) — shows loading spinner while saga runs
  • useSelector(state => state.feature.error) — shows error if saga fails
↓
2
Action creator 3 actions per feature
featureActions.js
  • featureRequest(payload) → { type: FEATURE_REQUEST, payload } — component dispatches this
  • featureSuccess(data) → { type: FEATURE_SUCCESS, payload: data } — saga dispatches on success
  • featureFailure(error) → { type: FEATURE_FAILURE, payload: error } — saga dispatches on failure
  • Never contains state logic — just describes what happened and carries the payload
↓
3
Constants 3 per async feature
featureConstants.js
  • FEATURE_REQUEST — dispatched by component
  • FEATURE_SUCCESS — dispatched by saga on success
  • FEATURE_FAILURE — dispatched by saga on failure
  • Shared between action creator, saga, and reducer — avoids typos
↓
4
Store single source of truth
store.js
  • createStore(rootReducer, applyMiddleware(sagaMiddleware)) internally does 3 things:
  • ① Receives the action from dispatch(action)
  • ② Passes action to Saga middleware — saga intercepts here before reducer
  • ③ Forwards action to rootReducer(state, action) after saga is done
↓
5
Watcher saga registers and listens
rootSaga.js
  • sagaMiddleware.run(rootSaga) — starts all watchers
  • all([...]) — combines multiple watcher sagas
  • takeEvery(FEATURE_REQUEST, featureWorkerSaga) — runs worker for every matching action
  • takeLatest(FEATURE_REQUEST, featureWorkerSaga) — cancels previous, runs only latest
↓
6
Worker saga handles side effects
featureSaga.js
  • Triggered when watcher detects matching action type
  • yield pauses execution and waits for result before moving to next line
try {
  const data = yield call(apiFunc)    // call async function
  yield put(featureSuccess(data))     // dispatch success to Store
} catch(error) {
  yield put(featureFailure(error))     // dispatch failure to Store
}
  • call(fn, args) — calls async function, keeps saga testable
  • put(action) — dispatches action to Store (saga's version of dispatch)
  • select(selector) — reads current state from Store inside saga
↓
7
Root reducer registers reducers
rootReducer.js
  • combineReducers({ feature: featureReducer }) — you pass reducers, not actions
  • Action broadcasted to every registered reducer by Redux internally
  • Each reducer checks action.type — handles it or returns default state
↓
8
Reducer decides new state
featureReducer.js
  • Initial state: { data: [], loading: false, error: null }
  • case FEATURE_REQUEST → { ...state, loading: true, error: null }
  • case FEATURE_SUCCESS → { ...state, loading: false, data: action.payload }
  • case FEATURE_FAILURE → { ...state, loading: false, error: action.payload }
  • default returns current state unchanged
↓
9
Store saves new state
  • New state committed to the store internally by createStore
  • <Provider store={store}> in App.jsx watches the store and notifies all components using useSelector
↓
10
Component re-renders
  • useSelector(state => state.feature.data) — gets updated data
  • useSelector(state => state.feature.loading) — hides spinner
  • useSelector(state => state.feature.error) — shows error if any
  • React re-renders only the affected component

Key concepts

useDispatch — calls action creator first, then sends returned action object to Store
useSelector — component reads state from Store
Saga sits between Store and Reducer — intercepts actions, handles side effects, dispatches new actions
yield — pauses saga execution and waits for result before continuing
call() — runs async function, keeps saga testable
put() — dispatches action to Store from inside saga (saga's version of dispatch)
select() — reads current Redux state from inside saga
takeEvery — runs saga for every matching action (allows parallel runs)
takeLatest — cancels previous run, keeps only the latest (good for search/fetch)
all([...]) — combines multiple watcher sagas in rootSaga
Three constants per async feature — FEATURE_REQUEST / FEATURE_SUCCESS / FEATURE_FAILURE
Initial state shape for async — { data: [], loading: false, error: null }
Reducer never talks to component directly — Store is always in between
Action creator describes what happened — Saga handles side effects — Reducer decides what changes
<Provider> — does not update state, just makes store accessible to all components
